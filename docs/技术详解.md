# 笔驭技术详解

本文描述当前主线代码的运行结构。它用于定位代码、判断数据写入位置和识别付费模型调用，不替代产品规范。

## 1. 运行边界

笔驭只有一套产品代码，通过运行角色区分作者正式使用和开发验收：

| 角色 | 默认端口 | 数据根来源 | 启动入口 |
|---|---:|---|---|
| production | 8080 | `runtime-production.json`，可由本次环境临时覆盖 | `scripts/start_biyu_ui.ps1` |
| development | 8090 | `runtime-development.json`，可由本次环境临时覆盖 | `scripts/start_biyu_dev.ps1` |
| test | 不固定 | pytest 会话创建的临时目录 | `tests/conftest.py` |

启动身份由代码仓、远端仓、提交 SHA、实际数据根和来源共同组成。来源为 `persistent` 或 `temporary override`。临时覆盖只影响本次进程，不回填持久配置。

启动时有三层闸：

1. `biyu.runtime_config.resolve_runtime_data_root` 要求角色持久配置存在，再解析本次环境覆盖。
2. `biyu.config.validate_runtime_binding` 校验角色、目录存在性和生产/测试隔离。
3. `biyu.ui.app.enforce_runtime_binding` 在 FastAPI startup 再次核对实际根与本次解析结果。

任何一层失败，服务在接受请求前退出。开发版禁止监听 8080；已有监听者由 `scripts/runtime_guard.py` 按命令行、代码仓和数据根识别。

## 2. 代码地图

### 入口与页面

- `src/biyu/ui/app.py`：FastAPI 应用、startup 闸、写保护、路由装配、`/api/version` 和静态页面。
- `src/biyu/web/routes.py`：书架、章节、正文与基础工作台 API。
- `src/biyu/ui/workbench.py`：章节工作台状态、导入、读稿、返修、记忆和采用/撤回流程。
- `src/biyu/ui/settings.py`：世界观、人物卡等设定读写。
- `src/biyu/ui/backup.py`：备份、回收站、恢复和章节清理。
- `src/biyu/ui/routes.py`：会话、立项、建议及 SSE 交互。
- `src/biyu/ui/static/`：作者浏览器界面。

### 写作与审读管线

- `src/biyu/pipeline.py`：章节生成总管线、Writer/Editor 循环、整章返修。
- `src/biyu/editor/editor.py`：单次编辑审读和结构化问题输出。
- `src/biyu/editor/multi_agent.py`：多阶段编辑与书级 `phase_trace`。
- `src/biyu/auditor/`、`src/biyu/lint_rules/`：确定性审计和规则检查。
- `src/biyu/observer.py`、`src/biyu/projections.py`、`src/biyu/memory_projection.py`：正式正文观察、记忆分片和重放。
- `src/biyu/importer/`：外部稿件预览、冲突判断和导入。
- `src/biyu/fingerprint/`：声纹提取、蒸馏、合并、版本和台账。

### 模型与成本

- `src/biyu/llm/registry.py`：读取模型目录，按别名或管线阶段创建适配器。
- `src/biyu/llm/*.py`：DeepSeek、GLM、Kimi、豆包和 OpenAI-compatible HTTP 适配器。
- `src/biyu/ui/cost_log.py`：根级中央成本台账。
- `src/biyu/cost.py` 与各管线 `_log_cost`：书级或章节级成本记录。
- `config/models.yaml.example`：不含私钥的模型目录样例；实际密钥由安全配置读取。

## 3. 主请求链

### 打开书架

```text
浏览器 GET /
  -> ui.app 返回静态页面
  -> GET /api/version 读取运行身份
  -> GET /api/books 枚举当前可见书
  -> config.get_data_root / find_book_dir
  -> 只读取包含 book.json 的书目录
```

打开书架和浏览书目本身不调用模型。

### 生成与审读一章

```text
作者在工作台触发生成
  -> Web/Workbench API 校验当前书和章节
  -> ModelRegistry 按 stage 取得 Writer / Editor adapter
  -> pipeline 组装设定、规划、前文、记忆和声纹
  -> Writer 生成候选稿
  -> Editor 审读并输出问题
  -> 必要时 Writer 按问题修订，Editor 可再次审读
  -> 确定性 auditor 补充规则结果
  -> 候选稿、审读报告、成本和过程证据写入当前书
```

候选稿先写入 `chapters/_pending/`。只有作者执行采用流程后才进入正式 `chapters/chN.md`，随后观察器更新记忆投影。返修包在调用前验证候选稿摘要，避免对过期版本付费和覆盖新稿。

### 导入外部稿件

```text
粘贴或选择稿件
  -> imports/preview 只在内存中拆分和检查冲突
  -> 作者确认
  -> imports 写入候选或正式正文
  -> memory/preview 对首章建立投影并展示
  -> 作者确认后继续其余章
```

基础导入返回 `llm_calls: 0`。后续记忆建立是否调用模型取决于现役观察器配置，调用证据和成本必须按实际结果记录。

### 记忆与撤回

正式正文通过观察器生成章节分片，再由 `memory_projection` 重放成当前记忆。作者钉住的事实独立保存；冲突必须显式选择。撤回正式正文时，正文退回候选状态，记忆按剩余正式章重放，不改动后续章节正文。

### 备份

`run_backup(source, destination, ...)` 的 `source` 是本次进程已经解析出的实际数据根。备份只复制包含 `book.json` 的书目录和根级 `cost_log.csv`；manifest 的 `source_path` 直接写 `source.resolve()`，不从持久配置反推。

## 4. 付费调用点

只有执行到 adapter 的 `generate(...)` 或声纹专用 `generate_json(...)` 才可能产生外部模型费用。主要入口如下：

| 作者动作 | 主要代码 | 调用特点 |
|---|---|---|
| 章节生成 | `pipeline.py` | Writer 调用；按配置可追加 Editor 和修订调用 |
| 工作台整章返修 | `pipeline.revise_chapter_from_package` | 一次 Writer 修订，随后一次 Editor 复审 |
| 编辑审读 | `editor/editor.py`、`editor/multi_agent.py` | 单阶段或多阶段模型调用 |
| 立项/提案 | `propose/`、`ui/orchestrator.py` | 路由、分析、红蓝评议和文案生成按流程调用 |
| 命名 | `ui/naming.py` | 作者明确触发候选生成时调用 |
| 摘要/诊断 | `ui/summarize.py`、`ui/diagnosis.py` | 作者明确触发时调用 |
| 声纹导入与蒸馏 | `ui/voiceprint_import.py`、`ui/voiceprint.py` | 提取或蒸馏时调用并写成本 |
| 责编会话 | `ui/routes.py` | 默认占位模式为零调用；只有关闭占位开关后才调用 |
| 连接测试 | `ui/setup.py` | 作者测试模型连接时发最小请求 |

保护原则：

- 打开页面、读取书架、编辑本地字段和预览基础导入不应产生模型调用。
- 模型调用结果携带 token 和 cost 时写入成本台账；成本写入失败会记录警告，但不伪造为零成本成功。
- 会话有软成本上限；达到上限后不继续生成。
- 润色默认关闭，作者模型面板不展示该阶段；重新启用属于单独产品验收。

## 5. 数据布局

```text
<BIYU_DATA_ROOT>/
  cost_log.csv                  # 跨书中央成本台账
  <book>/
    book.json                   # 书身份与基础配置，也是书目录判据
    characters.yaml             # 人物设定当前版本
    worldbook/                  # 世界观与真相文件
    outlines/                   # 章节细纲
    chapters/
      chN.md                    # 正式正文
      _pending/chN.md           # 候选正文
    logs/
      cost_log.csv              # 兼容/书级成本记录
      chN/                      # 章节过程、状态和返修包
    audit_reports/              # 审读与审计报告
    phase_trace/                # 本书编辑阶段追踪
    projections/                # 章节记忆分片
    fingerprint/                # 本书声纹资产与状态
```

实际目录由各模块按需创建；上图表示所有主要类型的归属，不表示每本书必然同时存在全部目录。

生产数据根顶层目录必须都是书，判据是该目录存在 `book.json`。根级普通文件可以包含中央账本；临时日志、固定工单目录、代码仓 `.git` 和测试输出不得出现在生产根顶层。

## 6. 数据根与写入路径

统一入口是 `biyu.config.get_data_root()`：只接受 `BIYU_DATA_ROOT`，缺失即抛错，不回落到用户主目录。启动器负责先从角色持久配置解析，再把实际值显式注入服务进程。

书解析通过 `find_book_dir` / `resolve_book_dir` 完成：先匹配 `book.json.id`，再兼容目录名。写请求经过 `ui.app._write_protection`，只有当前 primary 数据根拥有的书可以写；次级可见根只读。

主要写入归属：

| 数据 | 路径来源 |
|---|---|
| 正式/候选正文 | `resolved_book_dir / chapters` |
| 章节日志与返修包 | `resolved_book_dir / logs / chN` |
| 阶段追踪 | `resolved_book_dir / phase_trace` |
| 记忆分片 | `resolved_book_dir` 下的投影目录 |
| 声纹 | `resolved_book_dir / fingerprint` |
| 中央成本 | `get_data_root() / cost_log.csv` |
| 备份来源 | `run_backup` 收到的本次实际根 |

`tools/check_dataroot.py` 将这些关键不变式收敛为单一检查：显式根、禁止生产回落、测试隔离、书级阶段追踪、无固定追踪目录、备份运行时来源、生产顶层结构。有红项退出 `1`，否则退出 `0`；无法在当前角色核验的项目显示 `未做`，不伪报为绿。

## 7. 验证入口

- 默认回归：`.venv\Scripts\python.exe -m pytest -q`
- 数据根检查：设置 `BIYU_RUNTIME_ROLE=production` 后运行 `.venv\Scripts\python.exe tools\check_dataroot.py`
- 运行身份：`GET /api/version`
- 开发启动：`scripts\start_biyu_dev.ps1`
- 正式启动：`scripts\start_biyu_ui.ps1`

发布、同步正式仓和部署是独立动作。测试通过或本地真启动不等于已发布。
