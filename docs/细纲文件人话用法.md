# 细纲文件人话用法

> 写给作者：怎么给机器写细纲，让 AI 按你的规划写章节。

## 文件放哪

每个书目录下有个 `outlines/` 文件夹。细纲文件按章号命名：

```
data/<你的书>/
  outlines/
    ch1.md          ← 第 1 章细纲
    ch2.md          ← 第 2 章细纲
    ch3.md          ← 第 3 章细纲
    ...
```

## 文件长什么样

每章一个 `.md` 文件，分两部分：

```markdown
---
present_characters: [江叙白, 何沛, 老覃]
---

# 第 N 章标题

剧情要点:
1. 事件一
2. 事件二
3. 事件三

章末钩子: 一句话钩子
```

### 第一部分：YAML 头（两行 `---` 之间）

目前只有一个字段机器会读：

| 字段 | 必填？ | 什么意思 | 示例 |
|------|--------|----------|------|
| `present_characters` | 强烈建议 | 本章会出场的有名角色（用中括号括起来，逗号分隔） | `[江叙白, 何沛, 老覃]` |

机器用这个字段做两件事：
1. **写入 Layer 2 prompt**：告诉写手"本章正文中只能出现以下有名角色，新角色仅限路人NPC"
2. **参与声纹显示与检查**：不在清单里的角色如果在正文里大段出现，审计会报警

### 第二部分：正文（Markdown）

这是你真正要写的内容。机器会读「剧情要点」里的每一条事件。

建议格式：
```
剧情要点:
1. 具体事件，谁做了什么
2. 包含关键对话、动作、环境变化
3. 重要数字、时间、地点要写清楚

章末钩子: 本章末尾的悬念/转折/信息揭露
```

机器不读花哨的格式，只读文字本身。写得越具体，AI 产出越贴合。

## 机器怎么用这份文件

管线走两步：

1. **规划阶段（Architect / R1）**：读你的细纲 → 理解戏核、笔墨分配、要删减什么 → 输出一份"创作者细纲"
2. **写作阶段（Writer / V4）**：读规划 + 原始细纲 → 生成正文

所以细纲里写「剧情要点」就够了——Architect 会把它转化为更细致的规划。不用提前写"节奏快慢"或"这段多少字"。

## 已批规划怎么被消费（R1-1 新功能）

如果你对 Architect 自动生成的规划不满意，可以手动修改并让 Writer 直接消费你的版本：

### 文件位置与格式

规划件存放在 `data/<书>/logs/chN/planning.md`，格式与 Architect 输出相同：

```markdown
status: 已批
# 第 N 章创作者细纲

## 戏核
这一章的存在是为了...

## 戏核如何承载（含技法）
...

## 笔墨分配
...

## 与前后章的关系
...

## 硬信息锚点块
...
```

**关键字段**：首行必须是 `status: 已批`，机器才会跳过 Architect 直接消费这份规划。

### 消费行为

运行 `biyu write -c N -b <书>` 时：
- **有已批规划件**：跳过 Architect 节省成本，控制台显示 `检测到已批规划件,跳过 Architect: logs/chN/planning.md`
- **无规划件/未批**：照常跑 Architect
- **加 `--replan` 参数**：强制无视已有规划件，重新跑 Architect

### 规划履约检查（Editor 新增第 8 维）

当提供了已批规划件时，Editor 会新增「规划履约」检查维度，核对：
- **戏核位置**：规划标注的关键处是否给了足够笔墨
- **笔墨分配**：关键处/过渡处占比是否符合规划
- **承启关系**：承前启后的约定是否在正文中落实
- **锚点人物在场**：规划硬信息块列出的人物是否真的出场

偏离会作为 issue 报出，类型为「规划履约」。

### 典型工作流

1. `biyu write -c 1 -b 我的书` → Architect 生成初版规划
2. 读 `data/我的书/logs/ch1/planning.md`，手动修改戏核/笔墨分配等
3. 在文件首行加 `status: 已批`
4. `biyu write -c 1 -b 我的书` → 跳过 Architect，直接消费你的规划
5. Editor 自动核对规划履约，偏离会报 issue

## 一条就够了

- 只写事实性的事件清单，别写创作感想（"这里要写得感人"）
- 数字、时间、地名写准确，机器会照搬
- 角色全名保持一致（别一会"张老师"一会"老张"，除非角色档案里配了 aliases）
- 章末钩子建议单独一行，Architect 会根据它设计章末悬念
