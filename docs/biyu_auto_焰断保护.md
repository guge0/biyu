# biyu auto 焰断保护

> 任务: T-P3-C P2-B 模块 11
> 日期: 2026-05-09

## 1. 调研结论

### 1.1 修复前状态

`biyu auto` 批量生成时**无任何失败保护**:

| 项目 | 修复前 |
|------|--------|
| 连续失败保护 | ❌ 无 |
| 单章重试 | ❌ 无(一次失败即跳过或崩溃) |
| 预算硬停 | ❌ 仅 warning,不中断 |
| 失败诊断报告 | ❌ 无 |
| 退出码 | ❌ 无(异常直接崩溃) |

### 1.2 失败判定标准

章节失败 = 写入 `_pending/chN.md`(而非 `chapters/chN.md`),触发条件:
1. Auditor BLOCK
2. 质量评分 overall < 3.5
3. 任何维度否决(dimension ≤ 1.0 或 character_consistency ≤ 2.0)
4. LLM 调用异常(超时/API 错误)

## 2. 实现方案

### 2.1 触发条件

满足任一即触发焰断:

| 条件 | 默认值 | 说明 |
|------|--------|------|
| 连续 N 章失败 | 3 | 含 BLOCK / 质量未达标 / LLM 异常 |
| 单章 retry 超限 | 5 | 同一章节连续重试仍失败 |
| 预算硬停 | ¥50 | 累计成本超过阈值 |

### 2.2 触发后行为

1. 立即停止,**不进入下一章**
2. 输出失败诊断报告(失败章节列表 + 原因 + 建议介入点)
3. 抛出 `CircuitBreakerTripped` 异常
4. **不删除已生成章节**,保留供排查

### 2.3 配置项

在 `models.yaml` 中可选配置(不配置则使用默认值):

```yaml
auto:
  consecutive_fail_threshold: 3   # 连续失败章数阈值
  per_chapter_retry_max: 5        # 单章重试上限
  budget_hard_stop: 50            # ¥,超过硬停
```
